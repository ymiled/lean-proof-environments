\title{\textbf{Proof-depth decay is not identifiable from depth sweeps:\\
an environment, a measurement, and four ways to build one wrong}}
\author{Youssef Miled}
\date{}

\begin{document}
\maketitle

\begin{abstract}
\noindent
Compositional proof pipelines are justified by a reported exponential decay in
model success with dependency depth, specifically ``roughly a 3x reduction in
successful problem count for every additional dependency solved.'' We build an
open Lean~4 environment to test that claim: lemma ladders with derived depths,
two conditions differing only in whether dependencies are supplied, and a reward
that audits which axioms a proof depends on rather than whether a file compiled.
One of our three ladders is the lemma chain of a security-type-system soundness
theorem that we machine-check end to end, giving a corpus with genuine
dependency structure and no plausible training-set contamination. We report a
robust condition effect: pooling depths $\ge 2$, supplying dependencies yields
$16/23$ successes against $0/9$ when they are withheld (Fisher exact
$p = 8.2\times10^{-4}$). We then argue that the headline quantity people want
from such sweeps, a per-depth decay constant, is \emph{not identifiable} from
them. On our arithmetic ladder a fit against depth gives $1.73\times$ with
$R^2=0.930$, while refitting the same observations against lemma count gives
$1.44\times$ with $R^2=0.930$; depth and total proof length correlate at $0.98$
across our ladders, and the source work's own reported 17-line difficulty cliff
predicts our curve with no depth effect at all. We also measure the environment's
own noise floor at roughly $25\%$ using prompts that are byte-identical across
conditions by construction. Finally we document four benchmark-design failures,
including a self-check that reported success for the entire life of a family
while four of its fourteen lemmas carried fabricated dependencies.
\end{abstract}

\section{Introduction}

Verification is an attractive target for reinforcement learning because the
reward is a proof kernel rather than a learned proxy or a test suite. A recurring
empirical claim in this area is that success decays sharply with the number of
dependencies a model must establish itself, and that supplying already-verified
dependencies as trusted interfaces is therefore the right architecture. The
specific figure we test, from Theorem's \texttt{lf-lean} report, is a
$3\times$ reduction per additional dependency, with monolithic translation
estimated below $20\%$ success.

That figure has been measured once, on one corpus, with one pipeline. We set out
to reproduce it and instead found that the experimental design used to produce
such numbers cannot separate the hypothesis of interest from a mundane
alternative. Our contributions are an environment, one statistically supported
effect, one identification argument, and a set of negative results about how to
build these benchmarks.

We are explicit about what this is not. There is no training here: the policy is
frozen and this is the environment half of an RL setup. And our sample sizes are
small, for reasons given in Section~\ref{sec:lim}. We regard the environment and
the identification argument as the contribution, not the decay constant.

\section{The environment}

\paragraph{Ladders and depth.}
A family is a Lean theory together with a dependency graph over lemmas. Depth is
derived from the graph, never declared: a lemma with no dependencies has depth
$1$, otherwise depth is one more than its deepest dependency. Derivation matters
because hand-written graphs drift, as Section~\ref{sec:neg} documents.

\paragraph{Conditions.}
A task is a set of lemmas to prove; every other lemma in the family is supplied
already proved. \emph{Compositional} is the singleton $\{L\}$. \emph{Monolithic}
is $\{L\}\cup\mathrm{ancestors}(L)$. Both are instances of one mechanism, which
also admits arbitrary intermediate sets.

\paragraph{Reward.}
A candidate is accepted only if the file compiles, \texttt{\#print axioms} on
every target is contained in
$\{\texttt{propext},\texttt{Classical.choice},\texttt{Quot.sound}\}$, and no
banned tactic appears in the model's text. Multi-lemma tasks are graded
all-or-nothing.

The axiom audit is not redundant with compilation. During development a lemma
failed to prove; Lean reported the error and still declared the theorem, and every
downstream lemma citing it compiled with exit status $0$ and no diagnostics. Only
\texttt{\#print axioms} revealed \texttt{sorryAx} three rungs later. A reward
based on compilation would have scored that subtree as proved.

\paragraph{Preventing statement drift.}
The policy never writes the theorem statement. The harness emits the
\texttt{theorem \ldots := by} header and splices in a tactic block only, so a
model cannot weaken, restate, or substitute the goal. This removes a large class
of reward hacking structurally rather than detecting it.

\paragraph{Certification.}
Before any sweep, each rung is checked to be provable in both conditions, and each
declared dependency is checked to be real by compiling the rung with its ancestors
absent from the file entirely.

\section{Corpora}

Two families are theories written for the purpose: a Peano development
(15 lemmas, depths 1--5) and a small security type system (12 lemmas, depths
1--4). The third is not written for the purpose.

We machine-checked, in Lean~4, the soundness theorem of a security type system in
the Volpano-Smith-Irvine style with subtyping, while loops, and a function
extension. The formalisation is 784 lines with no \texttt{sorry}; axioms are
limited to \texttt{propext} and \texttt{Quot.sound}. Semantics is fuel-indexed, so
the theorem is termination-insensitive, relating runs that both terminate.
Expression agreement and command noninterference must be proved simultaneously by
induction on fuel, because a call inside an expression executes a command while an
assignment inside a command evaluates an expression.

We use its lemma chain as the third ladder (14 lemmas, depths 1--5). Two
properties motivate this. The depths are the dependency structure the proof
actually has, so the ladder cannot have been shaped to produce a curve. And the
system does not appear in any public corpus, unlike Peano arithmetic, which
removes the dominant contamination concern.

\section{Experiments}

All results use one-shot policies with no compiler access, so a model cannot
iterate against the kernel. Reference and empty policies bound the environment:
the reference solution scores $1.00$ in every cell and a trivial \texttt{rfl}
policy scores $0.00$, confirming the grader discriminates.

Per-cell intervals are wide. Pooling the cells where the conditions actually
differ, that is depths $\ge 2$, gives compositional $16/23$ ($[0.49,0.84]$)
against monolithic $0/9$ ($[0.00,0.30]$), Fisher exact two-sided
$p = 8.2\times 10^{-4}$. Supplying dependencies has a large effect on this
corpus.

The depth-5 compositional cell at $1.00$ is informative rather than anomalous:
that theorem is a one-line application of the lemma directly beneath it, which
the compositional condition supplies. Depth and difficulty decouple precisely
when interfaces are handed over.

\subsection{The decay constant is not identifiable}

On the arithmetic ladder, Haiku~4.5 monolithic pass rates fall
$1.00, 0.75, 0.33, 0.00, 0.00$ across depths 1--5. Regressing $\log(\text{pass})$
on depth over the non-zero points gives
\[
1.73\times \text{ per depth},\qquad R^2 = 0.930 .
\]
Regressing the identical observations on \emph{lemma count} instead gives
\[
1.44\times \text{ per lemma},\qquad R^2 = 0.930 .
\]
The two models fit equally well to three decimal places. This is not a
coincidence of one ladder: across our families the correlation between depth and
total monolithic proof length is approximately $0.98$, because monolithic length
is by construction the sum over ancestors.

The alternative hypothesis is concrete rather than rhetorical. The same
\texttt{lf-lean} report documents a difficulty cliff at ``17+ marginal LoC.'' In
our arithmetic ladder, monolithic length crosses seventeen lines between depths
3 and 4. A pure length-cliff model with no depth term predicts our observed curve.

We therefore do not report $1.73\times$ as a replication of $3\times$. We report
that depth sweeps of this form cannot distinguish compounding from volume.

\paragraph{A design that would.}
Compare $k$ mutually independent lemmas against $k$ chained ones at matched count
and matched total length. Equal rates implicate volume; a gap implicates
chaining. Two constraints make this harder than it appears. Withheld sets must be
upward closed, so independent sets can only be drawn from maximal elements, and a
funnel-shaped family supports no such comparison at any $k$. And matched pairs
cannot be constructed by making every rung the same shape, because uniformity
makes chains bypassable by unfolding (Section~\ref{sec:neg}). Pairs must be
searched for. We locate exactly length-matched pairs at $k=2,3$ in the arithmetic
family, but have run the contrast only against a policy that ceilings on it.

\subsection{Noise floor}

Depth-1 lemmas have no ancestors, so their monolithic and compositional prompts
are byte-identical, which we verify with \texttt{diff}. They are nonetheless
answered by independent policy instances under different labels. In one sweep
these identical prompts scored $8/8$ in one arm and $6/8$ in the other, placing
run-to-run variance near $25\%$. Depth-1 rungs thus act as a built-in replication
control, and we recommend any benchmark of this shape include one deliberately.

\section{Four benchmark-design failures}
\label{sec:neg}

\paragraph{Closed goals collapse depth.}
Stating lemmas at a concrete point produces goals that are closed terms, which
\texttt{simp} evaluates rather than reasons about. A depth-3 rung fell to
\texttt{simp\_all} with no lemmas in scope. The ladder compiled and measured
nothing. Rungs must quantify over the variables the definitions recurse on.

\paragraph{Uniformity destroys essential depth.}
A family built so that chain and independent arms match exactly failed, because
when each rung is the previous one composed once more the chain is bypassable by
unfolding definitions and reusing the base lemma. We verified this by compiling
the depth-4 lemma with the two beneath it deleted. Exact matching requires
uniformity and uniformity makes dependencies decorative.

\paragraph{Graph shape determines feasible experiments.}
Because withheld sets are upward closed, independent sets exist only among maximal
elements. A family with one maximal element admits none at all. Our security
family originally had exactly one, making the identification contrast impossible
rather than merely underpowered.

\paragraph{An inert safeguard is worse than none.}
The dependency-reality check was vacuous for multi-lemma tasks: it graded a
monolithic task using the single-lemma solution, so missing blocks were filled
with \texttt{sorry} and the audit rejected the attempt for the wrong reason,
making the failure branch unreachable. It reported success for the entire life of
one family while four of its fourteen lemmas declared dependencies their proofs
never cite, inflating depths and invalidating every depth-indexed number from it.
It was found by inspection, not by the check. The repair compiles each rung with
ancestors absent from the file and derives the graph from proof text.

\section{Limitations}
\label{sec:lim}

Sample sizes are small: cells contain between 2 and 12 attempts, and an API rate
limit halted our sweep at 50 of 140 planned tasks. Only the pooled comparison in
Section~4.1 is adequately powered; no per-cell number should be read as precise,
and no constant should be fitted to Table~\ref{tab:vsi}.

Results cover two model families. Episodes are single-step, with one attempt and
one binary reward; per-tactic actions with intermediate proof states would require
a persistent Lean server. The renaming defence against contamination is untested,
though the machine-checked ladder largely sidesteps the issue. The soundness
theorem we prove is termination-insensitive.

Finally, we do not train. Attaching a learner to the provided
\texttt{reset}/\texttt{step} interface is future work, and we consider the
calibration problem below a precondition for it.

\section{Conclusion}

Our clearest practical finding is not about depth. The grader, the dependency
machinery, the renaming, and the certifications all worked once repaired, and
none was the bottleneck. The bottleneck was difficulty calibration: a strong model
ceilings on the arithmetic ladder, the first version of the security ladder floored
above depth 1, and only a weaker model or a rebuilt ladder produced a measurable
curve at all.

Tasks that always succeed and tasks that always fail both yield zero gradient,
which is the sparse-reward failure usually attributed to unit tests. Dense
feedback is therefore not a property of proof assistants. It is a property of a
task distribution matched to a policy. Proof assistants make dense feedback
possible and do not make it automatic, and scaling reinforcement learning on
verification requires a calibration story in addition to a kernel.

\section*{Reproducibility}

The environment, grader, three families, the 784-line machine-checked
formalisation, and a design log of every failure in Section~\ref{sec:neg} are
released. \texttt{selftest} certifies a family before any sweep and must report
zero failures. Sweeps are split into a prompt-export and a grading phase so that
policies without an HTTP API can be evaluated, and the runner emits the safe
partition of tasks across policy instances, since a compositional prompt supplies
its target's ancestors together with their proofs and so leaks answers if batched
carelessly.
