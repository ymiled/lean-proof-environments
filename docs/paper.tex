\section*{Why}

As an undergrad I built a security type system for a small imperative language
and wrote a paper proving it sound. The implementation was OCaml: an explicit
datatype for proof trees, and a checker that decides whether a given tree really
proves that a given program has a given type. The soundness theorem itself, that
every well-typed program is noninterferent, was argued by hand in the paper.

That split is normal. Almost all programming-language metatheory works this way,
and nobody thinks worse of it. But it does mean the strongest claim in the
project rested on my own prose and my own checker, both of which I wrote. So I
went back and machine-checked the theorem in Lean 4.

The result is 784 lines. It has no \texttt{sorry} anywhere, and
\texttt{\#print axioms} on the final theorem reports only \texttt{propext} and
\texttt{Quot.sound}, both of which are standard and arrive through
\texttt{simp} and \texttt{omega}. Anyone can check that in about thirty seconds.

\section*{What the system is}

The language has expressions, assignment, sequencing, conditionals, while loops,
and functions. Every variable is labelled either public or secret. The attacker
is assumed to see the public variables and nothing else, and the question is
whether running a program can move information from the secret side to the
public side.

The obvious rule, never assign a secret expression to a public variable, catches
the direct leak and misses the interesting one:

\begin{lstlisting}
if secret_y = 0 then public_x := 1 else public_x := 2
\end{lstlisting}

No secret value is assigned to \texttt{public\_x} here. But afterwards, reading
\texttt{public\_x} tells you whether \texttt{secret\_y} was zero. The information
travelled through which branch ran. Handling that is the whole reason the type
system carries a program counter level, and the reason the soundness proof needs
a confinement lemma.

My original system follows Volpano, Smith and Irvine, with subtyping. Command
types carry two levels, $\mathsf{Cmd}(\tau_1,\tau_2)$, and subtyping is
contravariant in the first. There is also a judgment
$\mathsf{Ncmd}(\tau,n)$ carrying a nesting-depth counter, where the conditional
rule demands its branches at $n-1$. On top of that I added function types,
$\mathsf{Func}(\tau_1,\tau_2)$, with definitions, calls and returns, which is the
part of the system that is mine rather than the literature's.

\section*{Getting it into Lean}

Three decisions did most of the work, and I want to be concrete about them
because they are what made the thing finishable rather than a six-month project.

\textbf{Semantics is a total function, not an inductive relation.} Most
formalisations define evaluation as a relation and then reason by induction over
derivations. I made \texttt{evalC} a function from a state and a command to a
state. That means every proof goes by structural induction plus \texttt{simp},
and I never had to build the derivation-induction machinery. The cost is that
while loops do not terminate, so evaluation is indexed by fuel and returns
\texttt{Option}. That is not a dodge, it changes the theorem: what I prove is
termination-insensitive noninterference, relating two runs that both finish. For
a language with loops that is the correct statement anyway.

\textbf{Typing is \texttt{Bool}-valued where it can be.} Well-typedness of a
command against a program counter level computes. So a hypothesis
\texttt{wt G pc c = true} can be taken apart by \texttt{simp} instead of by case
analysis on constructors.

\textbf{Expression typing is not mutual with command typing.} They look mutual,
but expression typing never mentions command typing, and Lean's
\texttt{induction} tactic refuses mutually inductive types. Splitting them was
the difference between being able to do induction at all and not.

\section*{The two things that were actually hard}

\textbf{Subsumption makes inversion painful.} Because the typing relation has a
subsumption rule, a derivation can end in \texttt{sub} at any point. Every
inversion lemma therefore has an open case where you know nothing about how the
type was reached. The lemma that unlocks this says that only a base type can
subtype into a base type, and the levels are ordered:

\begin{lstlisting}
theorem sub_base_inv (h : SubTy t (.base b)) :
    exists a, t = .base a /\ a.le b = true
\end{lstlisting}

It goes by induction over the subtyping relation, including its transitivity
constructor, and once it exists the rest of the inversions are mechanical. There
is also a proof-engineering trap here that cost me an hour: the natural move is
\texttt{generalize h : X = y at hyp}, but that rewrites the goal as well as the
hypothesis, which silently breaks the subsumption case whenever the conclusion
mentions the type being inverted. Stating the index equations as explicit
hypotheses instead works everywhere.

\textbf{Expressions and commands have to be proved together.} A function call
sits inside an expression and runs a command. An assignment sits inside a command
and evaluates an expression. So neither statement can be established before the
other. What breaks the circularity is fuel: at fuel $k+1$ every recursive use is
at fuel $k$, so the two halves can be proved simultaneously by induction on fuel.

\begin{lstlisting}
theorem agree (hft : FTOk G sg ft) : forall k,
   (forall e, TyE G sg e (.base .L) -> ... -> v = w)
/\ (forall c ty, TyC G sg c ty -> ... -> lowEq G s' t')
\end{lstlisting}

The call case then works by noticing that binding the same argument value into
both states preserves public agreement, applying the command half to the function
body, and reading the return variable at its declared public level. That last
step needs the restriction from my original OCaml rules, where a function call is
only well-typed when its parameter level is public.

The other case worth mentioning is the conditional with a secret guard. There the
two runs may take different branches, so there is no induction hypothesis
relating them. Instead you show separately that neither run moved the public part
of the state, using confinement, and then chain:
$c(s) \approx_L s \approx_L t \approx_L c(t)$. That chain is why reflexivity,
symmetry and transitivity of public agreement exist as lemmas at all. They look
like boilerplate and they are load-bearing.

\section*{What is new here and what is not}

The mathematics is textbook. Volpano-Smith-Irvine noninterference is a known
result and I am not claiming otherwise. What is mine is the function extension,
which does not appear in the published rules, and the formalisation, which as far
as I know does not exist for this particular combination of subtyping, loops and
functions.

The honest summary is that this is engineering, not a new theorem. Its value is
that a hand argument about a system with subtyping and a nesting counter and
function calls is exactly the kind of argument that quietly hides a case, and now
it does not.

\section*{A second use for the proof}

Once the proof existed I noticed its lemma chain is a dependency graph with real
depths, from the lattice lemmas at the bottom to soundness at the top, and that
this makes it a decent test set for how well models prove things at depth. So I
built a small environment around it: pose each lemma either with its dependencies
already supplied or with them withheld, grade with the Lean kernel, and audit
\texttt{\#print axioms} rather than trusting that the file compiled.

That audit is not paranoia. While building this, a lemma failed to prove, Lean
reported the error, and the theorem was still declared. Everything downstream that
cited it compiled with exit status 0 and no complaints. Only the axiom check
showed \texttt{sorryAx}. A grader that asks whether the file compiled would have
scored that whole subtree as proved.

Running one frontier model over the ladder one-shot, with dependencies supplied
it proves between half and all of the lemmas at every depth; with them withheld it
drops to zero from depth two upward. I am not going to make more of that than it
deserves. The sample sizes are between two and twelve per cell, an API limit cut
the sweep off part way, and on a separate arithmetic ladder I found that a decay
curve fitted against depth and the same curve fitted against sheer number of
lemmas are statistically indistinguishable, which means this kind of measurement
cannot by itself tell you that depth is what matters.

\section*{Limitations}

The theorem is termination-insensitive, which is forced by fuel and is standard
for languages with loops, but it does mean a program that diverges on secret data
is out of scope.

The formalisation covers the type system I designed, not every rule in the OCaml
checker. The subtyping relation and the command and function types are there. The
nesting counter is present in the types and the rules but the metatheorem does not
say anything specific about it.

And the benchmark half is underpowered. It is a working environment with real
graders and honest negative results, not a study.

\section*{Artifact}

\texttt{lean/Vsi.lean} is the formalisation. \texttt{lean/README.md} says what is
proved and what is not. \texttt{docs/design-log.md} records the things that went
wrong on the way, including two ladder designs that turned out to measure nothing
and a self-check that was inert for the entire life of one family, which I only
found because a dependency looked implausible on inspection.
